# FOTO unified workflow checkpoint — September 9, 2026

This is a private-branch implementation checkpoint, not a claim that the full
approved plan or hosted release is complete. Local application: `npm run dev:lab`,
`http://127.0.0.1:8085`. Production must not use the lab authentication bypass.

## Implemented and verified locally

- Studio folder drops enter full Develop. Cull and Develop share the
  account-and-shoot repository; old image-adjustment/export entry points open
  Develop instead of applying a competing Canvas treatment.
- Pending edits flush before route changes. Catalog reads cannot overwrite a
  newer Cull gesture; unchanged hidden views cannot clear selection, replace a
  different tab's selection, or erase an unsupported filter.
- Additive manifest/import-job stores, revision-checked writes, long legacy IDs,
  preserved original bytes/history/metadata, and immutable legacy treatment
  envelopes. Native conversion does not claim identical legacy pixels.
- Bounded discovery/preview/native-admission/commit queues. Pending identities
  are not verified photo identities. A successful transaction, not a finished
  preview, determines Saved. Import ownership survives route changes and HMR;
  no-lock tabs cannot steal another session's unfinished job.
- One FOTO sans-serif interface, black/light surfaces, and four flat Earnings
  charts: Collected, Expenses, Net and Refunds. Net uses signed colors; other
  activity is blue. Pies remain under closed Breakdown. Financial arithmetic
  is unchanged; zero activity is not fabricated.
- Google OAuth now distinguishes provider redirection from a successfully
  installed, verified account session. Returned session errors cannot report
  authentication success. Live provider completion is still unverified.

## Not yet release-complete

- The full cold/warm 1/337/1,000 real-file browser performance matrix, memory and
  responsiveness measurements are outstanding. Unit tests of 1,000 registered
  entries are not a RAW decoding, original-upload or durable-save benchmark.
- New import quality/face analysis remains pending and does not invent scores
  or rejects. Discovery streams registration, but heavy preparation currently
  waits for final enumeration/sidecar matching. Separate completion timings
  and versioned native source receipts need further work.
- Cull labels its unedited source preview honestly; it does not yet display
  every current native treatment as an edited Cull thumbnail.
- Complete migration of every named-project historical version, all requested
  failure-mode browser gates, portfolio client onboarding, live Google return
  flow, and the account-linked signed Mac companion remain open.
- Native processing is local-only. A web deployment is not a hosted C++ engine
  or a distributed Mac application. Full Lightroom/Pixieset parity is unclaimed.
- Private Git push, connected publishing branch, explicit Lovable publication
  to `lenslab.dev`, and live asset/auth readback are distinct release steps.
  Owner sign-in is required to verify/publish through the existing project.
- Neither `.env` nor `.env.development` belongs in this checkpoint's staging.
  Existing tracked environment history was not inspected or rewritten.

The existing overnight heartbeat continues from these open gates. It should
report usable milestones or required owner action, not repeated test noise.
